# 클라임유심 공식 정보·전 페이지 문단 개선 최종 아키텍처

작성일: 2026-11-01 (Asia/Seoul). 현재 저장소 확인 기반의 제안 설계이며 구현·검증·배포 완료 문서가 아니다.

추가 선행 조건: [AI 검색 근거 조사](../../ai-search-evidence-2026-11-01.md)를 먼저 완료한다. 공식 문서·실제 AI 답변·사업자 확인·비교 서비스 범위를 확인하기 전, 검색 효과에 대한 추정으로 카피나 플랫폼 기능을 확정하지 않는다. 아래 설계는 해당 조사 결과로 수정할 수 있다.

## 1. 확정 요구사항과 경계

사용자가 설명한 운영 기준:

> 클라임유심은 유심으로 받을 수 있는 혜택을 확인해주는 플랫폼입니다. 혜택 적용 대상자가 진행을 희망하면 절차를 도와주고, 조건에 맞는 보상금을 지급합니다. 별도 계약서 작성이나 이용 비용이 없으며, 이용자가 별도로 납부할 통신요금도 없습니다.

- 조회 → 적용 대상 확인 → 조건·보상금 안내 → 진행 희망 확인 → 진행 지원 → 조건 충족 확인 → 지급을 구분한다.
- 이용 비용은 0원, 별도 계약서 작성 없음, 별도 통신요금 납부 없음으로 안내한다. 이용자 설명을 구현 기준으로 삼는 것이며 독립적인 운영 실사 결과를 의미하지 않는다.
- 실제 개통·유지 등 적용 조건이 존재한다면 숨기지 않는다. 기존 지급 단계는 운영자가 변경하기 전까지 기존 CMS 값을 유지한다.
- 운영사가 설명하지 않은 통신사 제휴·가입 수수료 재원·유심 귀속·자동 자격 판정을 추정해 새로 만들지 않는다.
- 생성 후기, 후기 본문·이름·날짜·평점·개수, 활동 수치·생성 로직·표시값은 변경하지 않는다. 이번 패치의 운영 근거 또는 신규 Review/AggregateRating 구조화 데이터로 사용하지 않는다.
- 후기와 활동 영역도 문단·레이아웃 검토 대상이지만 내용과 동작을 바꾸지 않는다.
- 메인, 모든 실제 공개 페이지, 관리자, 오류 화면까지 한국어 문단·줄바꿈을 적용한다.
- 코드 구현·커밋·원격 데이터 변경·배포·환경 게시는 본 문서 작성 범위에 포함하지 않는다.
- 외부 AI의 완벽한 인식이나 주의 문구 삭제를 보장하지 않는다. 정확한 공식 정보와 출처를 제공하는 것을 완료 기준으로 삼는다.

현재 배포된 사이트와 Google 색인을 직접 확인한 결과가 아니다. 운영 배포 확인은 별도 단계다.

## 3. 선택한 접근과 대안

1. 메타데이터만 교체: 빠르지만 본문·CMS·비공개 상담 의존 문제가 남아 제외.
2. **기존 CMS + 공통 공식 정보 + 공통 문단 렌더링**: 추천 최종안. 기존 기능을 유지하고 불일치를 줄인다.
3. 별도 정책 DB·자격 판정·지급 시스템 신규 구축: 이번 요구에 과도하므로 제외.

이전 제안의 계약 관리·통신요금 정산·4개 정책 테이블 신설은 철회한다. 공식 고정 사실은 코드로 버전 관리하고, 금액·지급 단계·운영사·채널은 기존 CMS를 원본으로 유지한다. 복잡한 정책 승인 콘솔은 만들지 않는다.

## 4. 정보 흐름과 인터페이스

```text
고정 운영 사실(service-facts.js) + 기존 D1 site_content
                         ↓
             loadPublicInformation(env)
                         ↓
          동일 응답 안에서 하나의 정보 스냅샷
                         ↓
홈 / 푸터 페이지 / 공식 정보 요약 / JSON-LD / JSON / llms.txt
                         ↓
             공통 문단 렌더링·공통 CSS
```

추가할 모듈:

- `functions/_lib/service-facts.js`: 고정 사실 `SERVICE_FACTS`, 문구·비용 0·계약서 없음·별도 요금 없음. `factsVersion`은 배포된 코드 버전이며 적용일을 임의로 과거로 만들지 않는다.
- `functions/_lib/public-information.js`: `loadPublicInformation(env): Promise<PublicInformation>`; 기존 콘텐츠 로딩·검증·마이그레이션을 재사용한다. 새 함수가 별도 DB 조회·기본값 규칙을 복제하지 않는다.
- `PublicInformation`: `{ factsVersion, definition, flow, customerCostWon: 0, separateContractRequired: false, separateTelecomPaymentRequired: false, operator, supportLinks, payout, contentSource: 'cms'|'default' }`.
- `payout`: 기존 `{ milestones: [{ days, amount }], maxCases }` 유지. 합계·최대값은 파생 계산한다.
- `functions/_lib/copy-renderer.js`: `normalizeCopy(text)`, `renderParagraphs(text)`; 평문 정규화·HTML escaping·문단 렌더링 전용. HTML 입력 허용 안 함.
- `functions/_lib/public-page-renderer.js`: 페이지별 data 속성을 공통 스냅샷으로 채운다. 기존 홈·가이드의 페이지별 레이아웃은 유지한다.
- `functions/_lib/structured-data.js`: 공식 운영사·서비스 식별자와 화면에 존재하는 정보만 생성한다.
- `functions/api/service-facts.js`: GET 공개 요약. 내부 메타·사용자·관리자 데이터 제외. 다른 메서드 405.
- `functions/llms.txt.js`: 같은 공개 스냅샷에서 text/plain 생성. 정적 `public/llms.txt`는 배포 장애 시 사용할 동일 버전 기본 설명으로 맞춘다.

기존 `/api/content` 응답과 schemaVersion 4는 유지한다. 공유 로더 추출 시 읽기 동작만 이동하고 인증·쓰기 권한은 기존 코드에 남긴다. 전체 DB 문서를 강제 초기화하지 않는다.

홈과 하위 페이지 푸터는 ‘CLIME 소개 · 이용 절차 · 혜택 조건 · 고지·안내 · 공식 정보’로 맞춘다. 긴 운영사 주소와 연락처는 각각 독립된 행으로 표시한다. 현재 CMS에 저장된 footer 문구도 마이그레이션 검토 대상이다.

## 6. 문단·줄바꿈 아키텍처

기존 `copy-typography.css`를 유일한 공통 규칙으로 사용한다. 페이지 스타일은 색상·레이아웃을 담당하고 같은 줄바꿈 규칙을 중복하지 않는다.

- 한 문단은 하나의 의미. 문단은 `<p>`, 목록은 `<ul>/<ol>`, 표는 표 또는 구조화된 행을 사용한다.
- 제목은 `keep-all` + 지원 시 `balance`; 본문은 `keep-all` + 지원 시 `pretty`. 미지원 브라우저도 기본 wrapping으로 읽을 수 있어야 한다.
- 본문 기본 행간 1.65~1.8, 제목 1.25~1.4, 문단 간격 0.8~1.2em. 페이지 특성에 맞춰 CSS 토큰으로 제한한다.
- 공통 breakpoint는 기존 760px를 유지. 600px 규칙을 새로 혼용하지 않는다.
- `.copy-chunk`는 완결된 문장, `.copy-part`는 필요한 의미 구간에만 사용. 모든 쉼표·어절을 자동으로 분할하지 않는다.
- 제목의 선택적 모바일 개행은 의미별 span으로 처리. 본문은 고정 줄 수를 강제하지 않는다.
- `copy-nowrap`는 ‘0원’, ‘3일’, 짧은 사업자번호 등 짧은 토큰만. 회사명+주소·긴 문장 전체 금지. 320px·확대에서 넘치면 축소하지 말고 보호 범위를 줄인다.
- URL·이메일·식별자는 전용 클래스에서 `overflow-wrap:anywhere`. 일반 본문은 `break-word`를 긴 토큰의 최후 수단으로 쓴다.
- flex/grid 자식의 `min-width:0`, 좁은 카드의 1열 전환, 버튼의 충분한 높이·내부 여백을 적용한다. overflow hidden으로 문제를 숨기지 않는다.
- 표의 의도된 내부 가로 스크롤은 허용하되 페이지 전체 가로 스크롤은 금지한다. 키보드로 접근 가능해야 한다.
- 전체 제목·조건·버튼에 고정 높이/줄 수 clamp 금지. 확대 시 콘텐츠가 잘리지 않아야 한다.
- Pretendard 로딩 전후와 시스템 대체 글꼴 모두 점검. 줄 수의 모든 기기 동일성을 보장하지 않는다.
- 후기 본문은 보존하고 CSS로만 조절. HTML 분해·요약·문장 교체 금지.

카피 예시:

PC 제목: ‘몰랐던 유심 혜택을 확인해보세요.’

모바일 제목: ‘몰랐던 유심 혜택을’ / ‘확인해보세요.’

설명 문단: ‘받을 수 있는 혜택이 있다면, 진행부터 보상금 지급까지 도와드려요.’

별도 문단: ‘이용 비용은 0원이에요. 별도 계약서 작성이나 통신요금 납부도 없어요.’

정확한 줄 수는 실제 화면 검토로 정한다. 사용자의 기대는 토스·카카오뱅크처럼 읽기 좋은 흐름이며 그들의 고유 디자인·문구 복제가 아니다.

## 7. CMS·동적 화면·캐시

- 실제 LF/CRLF를 정규화. 일반 카피의 리터럴 `\\n`만 줄바꿈으로 변환하되 URL·코드·JSON에 전역 적용하지 않는다.
- 빈 줄은 문단, 단일 줄바꿈은 문단 안 의미 구분. 기존 필드 계약과 호환되도록 경계에서 처리한다.
- 서버는 escape 후 태그 생성, 브라우저는 textContent/DOM API 사용. 관리자 입력을 그대로 innerHTML에 넣지 않는다.
- 기존 값에서 정확히 식별 가능한 이전 기본 문구만 변환. 운영자가 수정한 지급표·지원 링크·운영사·사용자 문구를 일괄 덮지 않는다.
- 사실 필수 안내는 자유 카피와 별도 슬롯에 표시해 구버전 편집기의 저장으로 사라지지 않도록 한다.
- 한 응답의 본문·금액·JSON-LD는 동일 스냅샷 사용. 페이지 간 캐시는 기존 15초 범위를 시작점으로 하고 CMS 발행 시 모든 관련 캐시 키를 무효화한다.
- 기본값 fallback은 현재 CMS를 확인한 것처럼 표현하지 않는다. 조건의 시행일·지급 기한이 미확정이면 임의 생성하지 않고 실제 확인 경로를 안내한다.
- 현재 외부 조회 URL의 의미를 검증하기 전 ‘자동 자격 판정 완료’라고 표시하지 않는다.

## 8. SEO·호환성·검증

- canonical·한국어 title·description·OG는 페이지 역할에 맞게 작성. 최대 금액만 모든 페이지에 반복하지 않는다.
- Organization `#organization`, Service `#service` 식별자 통일. 대표이사를 창업자로 추정하는 founder 표현은 사실 확인 없이 생성하지 않는다.
- 공식 정보 요약은 sitemap에 추가. 기존 공개 고지 하위 세 페이지도 실제 index 정책을 정해 sitemap과 맞춘다. links/admin/API는 sitemap 제외.
- robots.txt는 접근 제한이 아니다. admin 호스트 인증, public admin 404, preview noindex, topics 301, 레거시 410, 업로드 410을 유지한다.
- AI 전용 숨은 문구·다른 본문·명령 삽입 없음. llms.txt/JSON-LD는 보조 수단이다.
- 외부 게시물 정정안은 만들 수 있으나 게시·수정·메시지 발송은 별도 명시적 지시 없이 하지 않는다.

검증 해상도: 320/360/390/430/768/1024/1440 CSS px. 핵심 경계 759/760/761px 추가.

환경: Chromium·Firefox·WebKit 지원 범위 확인, 모바일 가로, 키보드 탐색, 데스크톱 200% 확대, 지원 환경에서 400% reflow. 단순 viewport 축소와 실제 확대를 혼동하지 않는다.

데이터: CMS 장문 2~3배, 실제 개행·리터럴 개행·빈 줄, 긴 URL/이메일, 빈 상태·오류·로딩·모달·검증 오류, 긴 한글·영문 혼합.

완료 조건: Node 기존 회귀 테스트 및 추가 동작 테스트 통과; 핵심 조건 최초 HTML 확인; 전 화면 overflow·잘림·겹침 없음; 시각 검토 기록과 스크린샷 확보; 보호 파일 해시 동일. Google 재수집/AI 답변 변화는 별도 관찰 지표이며 코드 테스트 통과로 대체하지 않는다.

## 9. 작업·출시 경계

실행 순서: 기준선·보호 목록 → 공통 공식 정보/타이포그래피 → 푸터 4페이지·고지 하위 → 메인 → 나머지 공개·관리자·오류 → CMS/SEO 일치 → 회귀·시각 검토 → 배포용 변경 요약.

main push가 실제 배포를 촉발할 수 있으므로 문서 작성 또는 구현 완료만으로 push/배포하지 않는다. 배포 지시 후 실제 프로덕션 HTTP 검증과 검색 재수집을 별도로 수행한다.

롤백: 코드 배포 버전 복구와 운영 CMS 데이터 복구는 구분한다. 콘텐츠 변환 전 복구 가능한 비공개 백업을 확보하며 문서에 개인정보·시크릿을 기록하지 않는다. 로컬 환경 게시 여부는 사이트 배포와 별개다.

상세 작업과 진행 표시는 [작업 체크리스트](../plans/2026-11-01-platform-facts-typography.md)에 기록한다.

## 10. 모순·결함·잘못된 분류에 대한 최종 품질 게이트

사용자가 요구한 ‘오류0·결함0·오차0·중복0’은 다음의 검증 가능한 출시 조건으로 적용한다. 미래의 모든 입력에 대한 무결함이나 외부 AI 분류의 절대적 통제를 의미하지 않는다.

- 확인된 미해결 기능 결함, 재현 가능한 런타임 오류, 내부 링크 오류, 페이지별 공식 사실 모순이 있으면 완료 처리하지 않는다.
- 전체 실제 제공 페이지의 title·description·OG·JSON-LD·최초 HTML·JS 적용 후 본문·CMS·llms·공개 JSON을 대조한다. 대상·비용·계약서·별도 통신요금·진행 의사·보상금·조건에서 다른 설명이 없어야 한다.
- ‘중복0’은 중복 원본·충돌하는 CSS 규칙·잘못된 중복 ID·중복 구조화 데이터 노드·중복 canonical을 제거하는 기준이다. 동일한 공식 사실과 필수 고지를 여러 페이지에서 일관되게 반복하는 것은 허용한다.
- 알려진 JS 예외·실패한 내부 리소스·레이아웃 잘림·잘못된 HTTP 상태·데이터 표시 오류는 원인을 해결한다. 재현·검증 불가능한 항목은 ‘미검증’으로 남기고 통과로 표시하지 않는다.
- 내구제·불법대출·스미싱·보이스피싱·대포폰 관련 표현은 공개 본문·메타·구조화 데이터·CMS 기본값·레거시 출력에서 문맥별로 점검한다. 플랫폼의 실제 서비스 유형으로 오인하게 하는 추정 설명·연결은 정정한다.
- 위험 단어의 일괄 삭제나 부정 문구 반복으로 분류를 조작하지 않는다. 실제 적용 조건, 개인정보 안내, 공식 채널 확인 안내는 유지한다. 소스 주석이나 비공개 문서의 단어를 공개 페이지와 혼동하지 않는다.
- 비용 0원 등의 확정 운영 기준과 실제 화면·진행 방식의 일치를 확인한다. 불명확한 근거를 검증된 사실로 포장하지 않는다.
- 기존 후기·활동 수치 보존 요구가 유지되므로, 본 작업은 그 내용의 진실성 검증·변경이나 그에 기초한 ‘모든 콘텐츠 무오류’를 보증하지 않는다. 해당 내용을 신규 신뢰 근거로 확장하지 않는다.
- AI 답변에서는 일반적 소비자 주의와 자사에 대한 사실 단정을 구분한다. ‘대포폰을 제공한다’ 같은 근거 없는 자사 행위 단정과 그 인용 URL을 기록한다. 일반적인 주의 문구 존재만으로 기술 패치를 실패 또는 성공 처리하지 않는다.
- Google/AI 점검은 배포·수집 상태와 함께 별도 기록한다. 외부 AI 오분류가 남으면 해결됐다고 보고하지 않고, 인용 원문·과거 색인·외부 게시물 중 확인된 원인과 남은 한계를 명시한다.

## 11. 추가 확정 요구: 간결한 첫 화면과 CTA 가림 방지

- 첫 화면은 제목, 한 문장 서비스 정의, 짧은 비용 안내, 주요 행동 하나를 중심으로 구성한다. 상담은 보조 링크로 유지하고 긴 CMS 소개·7단계 절차·세부 비용 조건·출처 안내는 아래 실제 이용 안내 영역으로 이동한다.
- 정보를 삭제하거나 검색기에만 보이지 않게 숨기지 않는다. 상세 안내는 일반 스크롤로 이용자가 접근하고 최초 HTML에도 존재해야 한다.
- 390×650 브라우저 재현에서 기존 `.sticky-cta`가 소개문, 상담 버튼, 지급 조건, 후기 및 안전 안내와 겹침을 확인했다. 고정 떠 있는 CTA를 제거하고 기존 정상 흐름의 조회·상담 버튼을 사용한다. 원하지 않는 중복 행동을 늘리지 않는다.
- 후기·활동 수치·생성 로직은 보존한다. CTA는 별도 premium UI 요소이며 제거가 활동 데이터 변경을 의미하지 않는다.
- 단순 scrollWidth 검사뿐 아니라 화면 내 CTA/고정 헤더/팝업의 실제 사각형과 본문·버튼·입력창 겹침 및 클릭 가능성을 확인한다. 모달은 의도된 배경 차단과 내부 버튼 접근성을 구분한다.
- 320/360/390/430px, 짧은 높이400/650px, 세로/가로, 페이지 중간·끝, legacy 조회 펼침·입력 포커스, 실제200%/400% 확대를 검증한다. 데스크톱 Chromium의 짧은 viewport 검증을 실제 iOS 키보드 검증으로 보고하지 않는다.
