# USIM PLUS 운영자 콘솔 설계

## 의도

현재 관리자 화면은 콘텐츠 편집과 사진 검토가 서로 분리되어 있고, 처음 운영하는 사람이 오늘 처리할 접수와 검토 우선순위를 한눈에 파악하기 어렵다. 데스크톱과 모바일에서 같은 보안 경계와 기능을 갖춘 운영 콘솔을 제공한다.

## 목표

- 대시보드, 미검토 접수, 전체 접수, 중복 의심, 안내 콘텐츠를 분명한 메뉴 계층으로 제공한다.
- 요약 지표, 접수번호, 시간, 상태, 비공개 사진, 관련 접수 신호를 표시한다.
- 모바일 서랍 메뉴와 터치 가능한 컨트롤로 주요 운영 작업을 수행할 수 있게 한다.
- 원본 IP를 저장하지 않는다. 접속 IP는 관리자 인증 비밀키로 만든 HMAC 비교값으로, 사진은 SHA-256으로 비교한다. 같은 IP만으로 동일인을 단정하거나 자동 승인·반려하지 않는다.
- 신청 관리 메타데이터와 비교값은 기존 60일 정리 주기를 따른다. 공개 개인정보 안내와 동의 문구를 갱신한다.
- 기존 D1, 비공개 R2, 비밀번호 세션 인증을 유지한다.

## 범위 밖

- 유저 계정, 전화번호·실명 기반 신원 확인, 알림 발송, 다중 운영자 권한 체계.
- 신청자의 원본 IP 저장, 자동 중복 판정 또는 자동 반려.
- 플랫폼을 벗어난 데이터 수집.

## 제약

- Cloudflare Pages Functions, D1, R2, 정적 HTML/CSS/JS로 구현한다. 런타임 의존성을 추가하지 않는다.
- 관리자 HTML/API는 `admin.climekr.com`과 기존 세션 인증에서만 동작한다.
- 사진 응답은 기존 비공개·no-store 정책을 유지한다.
- 기존 콘텐츠 편집과 승인·반려 동작은 유지한다.

## 접근 방식

1. 기존 페이지를 단순히 꾸민다: 가장 작지만 운영자가 접수량·이력·중복 근거를 찾는 문제가 남는다.
2. SPA/새 관리자 백엔드를 만든다: 자유도는 높지만 기존 보안·저장소에 큰 변경과 새 의존성이 필요하다.
3. 기존 Pages 관리자 위에 공통 반응형 메뉴, 대시보드와 목적별 접수 화면을 추가한다: 기존 세션·D1/R2를 재사용하면서 운영 흐름을 완성한다. **이 구현은 3번을 선택한다.**

## 사용자 흐름

- 로그인 후 대시보드에서 미검토 건수, 최근 승인·반려, 중복 의심을 확인하고 바로 해당 목록으로 이동한다.
- 미검토 화면에서 사진과 접수 메타데이터를 확인해 승인 또는 반려한다.
- 전체 접수 화면에서 상태를 필터링하고 처리 이력을 확인한다.
- 중복 의심 화면에서 같은 접속 신호 또는 동일 사진 파일의 접수 묶음을 확인한다. IP 원문과 비교 해시는 표시하지 않는다.
- 콘텐츠 메뉴에서 공개 안내 문구를 편집한다.

## 구현자가 결정할 세부 사항

접수 화면의 페이지 크기와 모바일 카드 배열은 기존 D1 keyset pagination과 CSS를 따라 정한다. UI는 한국어로 작성하고 모든 조작은 키보드와 스크린리더로 사용할 수 있게 한다.
